# L4 · 服务端防渗透（防 PentAGI & 黑盒复刻）

PentAGI 打的不是你的客户端，是你的**服务端 / 接口 / 部署**。黑盒复刻也靠大量打接口推测规则。这一层把"打接口"的成本抬到不值。

## 5.1 限流与异常检测（直接抬高成本）
- **分层限流**：按 IP / 账号 / 设备 / 接口维度限流，核心接口更严。
- **行为风控**：识别高频、规律性、覆盖式的探测（PentAGI 和黑盒采样都有明显模式）。
- **渐进惩罚**：异常流量先降速、再验证码、再临时封，而不是一刀切。
- 效果：PentAGI 的自动化高频探测会很快触发限流；黑盒复刻的大规模采样成本飙升。

## 5.2 鉴权与授权（服务端校验一切）
- **永远不信客户端**传来的身份、权限、会员状态、价格。
- 防 **BOLA/IDOR**：每个对象访问都在服务端校验归属（PentAGI 最爱找这个）。
- **JWT/OAuth** 正确实现：校验签名、过期、受众；别把敏感信息放可解的 payload。
- 最小权限：每个接口只给必要数据，不返回多余字段。

## 5.3 设备证明与客户端完整性
- **Play Integrity API（Android）/ App Attest（iOS）**：拦掉非正常客户端、模拟器、批量脚本的调用。
- **请求签名**：客户端对请求签名，服务端校验，防伪造/重放。
- 效果：黑盒复刻者没法用脚本大批量正常调用你的接口。

## 5.4 以攻代守（先自己扫）
- **自己先用 PentAGI / nuclei / ZAP 这类工具扫一遍**自己的系统（你有权测自己的）。
- 把 PentAGI 会找的洞（未授权接口、IDOR、注入、配置错误）先补掉。
- 别等复刻者先扫到。

## 5.5 基础设施
- WAF（挡常见注入/扫描）、最新补丁、最小暴露面、密钥管理（KMS/Secrets Manager）、日志与告警。

## ⚠️ 影响线上/资金的操作先经确认
限流阈值、封禁策略、WAF 规则这类会影响线上用户的改动，**先把方案给用户看，确认后再上**。纯加固代码可直接做。

## 验收
- [ ] 核心接口有限流 + 异常检测
- [ ] 服务端校验所有身份/权限/价格，无 BOLA/IDOR
- [ ] 有设备证明 / 请求签名
- [ ] 已自测渗透一遍并修复高危
