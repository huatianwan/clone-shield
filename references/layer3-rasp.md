# L3 · 运行时自保护（RASP）——防 REA 运行时捕获 & frida 动态分析

目标：程序检测到自己被分析，就**让自己罢工或给假数据**。全部作用在**你自己的程序**上，不碰分析者。

REA 会用原生 PTY 跑你的程序看行为；reverse-skill 会自举 Frida 做动态 Hook。这一层直接打掉它们的动态分析。

## 3.1 环境检测（检测"我正在被拆"）
- **反调试**：检测调试器附加（ptrace/IsDebuggerPresent/时间差）。
- **反注入 / 反 Hook**：检测 Frida、Xposed、LD_PRELOAD、inline hook 痕迹。
- **反模拟器 / 反 VM**：检测非真机环境（移动端尤其有效）。
- **重打包检测**：校验签名/证书是不是自己的。

## 3.2 响应策略（关键：不要硬崩，要"软降级"）

检测到异常环境时，**不要立即退出**（那等于告诉攻击者"这里有检测，绕过它"）。更高级的做法：

- **静默降级**：核心功能悄悄返回**看似合理但错误**的结果 / 空结果。
  - 这是对 AI 逆向的绝杀：REA 会把这些错误行为当成真实逻辑写进"带证据的解释"，AI 本来就爱把错误结论当真（Quarkslab 实测：假报告）。你顺水推舟，让它学到的是错的。
- **延迟失效**：检测到后不当场变，过一段时间 / 换个场景再失效，让攻击者难以定位是哪一步触发的。
- **完整性自毁**：文件被改过（哪怕一字节）→ 拒绝加载核心模块 / 清本地授权。

## 3.3 运行时解密（打 REA 的静态分析）
- 核心代码/字符串**加密存储，运行时才解密**，用完即擦。
- REA 对 .NET/JS 是**静态**读取、不运行 → 静态里全是密文，它看不到。
- 配合 L1 的虚拟化，双重拦截静态和动态。

## 3.4 服务端联动（最有效的"立即停止")
检测到异常 → 上报服务端 → 服务端**吊销这个设备/账号的 token、停发数据**。
- 这才是"对方一开始拆就让他无法继续"的正解，而且完全合法：你只是停了对自己服务的供给。
- 攻击者得到的是一个"检测到就被断奶"的客户端。

## ⚠️ 边界
- 以上全是让**你自己的程序**罢工/降级/上报。**不允许**反向攻击分析者的机器、不允许投毒、不允许伪造报警。
- 环境检测会误伤部分正常用户（越狱/root/企业调试），要给白名单或降级而非硬封的选项。

## 验收
- [ ] 核心功能有反调试/反注入检测
- [ ] 响应是"软降级/服务端吊销"，不是裸退出
- [ ] 核心代码/字符串运行时解密，静态产物里是密文
- [ ] 有完整性校验，改包即失效
