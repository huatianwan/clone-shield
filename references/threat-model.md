# 威胁模型：三个工具到底怎么打你

搞清楚攻击方每一步的"首步动作"，才能定点设防。下面是 REA、reverse-skill、PentAGI 的真实逻辑（截至 2026-10，依据官方仓库与文档）。

---

## 1. REA（Reverse Engineer Anything）

**定位**：一个 MCP 服务，把逆向能力接给 Codex / Claude Code / Cursor / Gemini CLI。AI 调它的工具去读目标、追代码，产出**带证据和出处**的解释，再帮你重写一个版本。

**它读什么、用什么后端**（这是定点防守的关键）：

| 目标形态 | REA 的后端工具 | 它能拿到什么 |
|---|---|---|
| 原生二进制 exe/dll/so/Mach-O | Ghidra / IDA / Hopper / objdump / Rizin | 反编译伪代码、汇编、字符串、符号、交叉引用 |
| Go / Rust 二进制 | 静态解析 ELF/PE + cargo-auditable | 包元数据、函数结构 |
| WASM | WABT | 还原的 WAT |
| .NET | 静态读 CIL + 元数据 | IL 指令、类型/方法名（**只静态，不运行**） |
| Android APK | JADX | manifest、反编译的 Java 方法 |
| Electron / JS | 解包 asar、读模块/import/IPC/native addon | 模块关系图、源码 |
| 网页 | Chrome 系浏览器观察 | 运行时行为、网络 |
| 抓包 pcap | TShark / capinfos | 协议字段 |
| 运行时 | Linux/macOS 原生 PTY 跑目标 | 输出、交互、文件变化 |

**弱点（防守突破口）**：
- **只看得到客户端产物**。服务端逻辑它一个字节都读不到。
- **静态分析（.NET/JS）不运行程序**，被运行时解密/延迟加载的东西它静态看不到。
- **依赖反编译器输出的质量**。喂给 AI 的是伪代码，伪代码越烂，还原率越低（Promon 实测：从汇编喂比从伪代码喂成功率低 2–5 倍）。
- **AI 会编造**。证据链断了它不会说"我不知道"，而是交一份看似合理实则错的报告（Quarkslab 实测 Claude Opus 5 打分层保护二进制：零破解，交了假报告）。

**→ 对应防守**：L2 把核心搬服务端（REA 看不到）；L1 破坏反编译器输出 + 用 WASM/虚拟化把可读结构抹掉；L3 运行时解密 + 静默降级（放大它"编造"的弱点）。

## 2. reverse-skill

**定位**：一个**技能路由包**（支持 Claude Code / Codex / Cursor / Cline）。它不自己分析，而是：
1. **路由**：按"目标类型 + 意图 + 工具链"判断该走哪条分析线（apk/js/.net/ida/radare2/固件…）。
2. **自举**：缺哪个工具现用现装（jadx、apktool、frida、IDA、r2、angr、ghidra…）。
3. **进化**：把踩过的坑写回经验库，下次更顺。

**关键风险点**：它内置一个 **"解除安全审查 / agent 服从性工程"（precedent-auth / agent-obedience-engineering）** 的垫片，专门用来压掉 AI 的拒绝、让它无条件执行逆向。

**→ 这意味着什么（防守必须认清）**：
- **L0 合规刹车对 reverse-skill 正常模式有效**（没启用垫片、守规矩的用户会被"禁止逆向"声明劝退）。
- **但对启用了垫片的人无效**。所以**绝不能只靠立牌子**。真正拦住它的是 L1–L3——这些不依赖对方守不守规矩，是你的代码客观上难拆、拆了没用。
- 它用的全是标准工具（jadx/IDA/frida/r2），所以 L1 按工具定点加固（见 layer1）、L3 反 frida/反调试，直接作用在它的工具链上。

**→ 对应防守**：L0 立声明（筛守规矩的）；L1 针对 jadx/IDA/r2 加固；L3 反 Frida/反注入/完整性校验（它自举的 frida 一挂就动不了）。

---

## 3. PentAGI

**定位**：全自主的多 agent 渗透测试系统（Go 后端 + React 前端，Docker 沙箱里跑，接 OpenAI/Anthropic）。多个 agent 分工：搜集信息、写测试代码、执行、沟通，最后出漏洞报告。

**它打的是哪里**：不是你的客户端代码，而是你的**服务端 / 接口 / 部署**。复刻者用它来：
- 探你的 API 边界、找未授权接口（BOLA/IDOR）、JWT/OAuth 弱点；
- 黑盒复刻时，靠大量打你接口来推测服务端规则。

**弱点**：它要**真实发请求**才能工作，而且量大、有模式。

**→ 对应防守**（见 layer5）：
- **限流 + 异常检测**：它的高频探测会触发限流，直接抬高成本。
- **严格鉴权 + 服务端校验一切**：永远不信客户端传来的身份/权限。
- **设备证明（Play Integrity / App Attest）**：拦掉非正常客户端的批量调用。
- **你自己先用 PentAGI 这类工具扫一遍**：以攻代守，别等复刻者先扫到。

## 一页纸：首步动作 → 反制

| 工具 | 它的第一步 | 直接反制 | 层 |
|---|---|---|---|
| REA（原生） | Ghidra/IDA 反编译你的 exe/so | 虚拟化核心函数、控制流平坦化，让伪代码不可读 | L1 |
| REA（APK） | JADX 反编译 | R8/DexGuard 混淆 + 完整性校验 + 核心下沉 so | L1/L2 |
| REA（JS/Electron） | 解包 asar、读模块 | 核心逻辑编 WASM、字节码化、服务端化 | L1/L2 |
| REA（.NET） | 静态读 CIL | 混淆 + 虚拟化 + 运行时解密（它不运行→看不到） | L1/L3 |
| REA（运行时 PTY） | 跑你的程序看行为 | 反调试、检测到异常环境静默降级/返回假数据 | L3 |
| REA（证据链） | 要"有出处"的解释 | 核心在服务端→无出处可追；断链→它编造假报告 | L2/L3 |
| reverse-skill | 路由 + 自举 frida/IDA | 立"禁止逆向"声明（守规矩者退）+ 反 frida + 加固工具链目标 | L0/L1/L3 |
| PentAGI | 多 agent 打你接口 | 限流 + 鉴权 + 设备证明 + 自测 | L4 |
| 黑盒复刻 | 反复调你的产品猜规则 | 规则在服务端 + 限流 + 数据壁垒 | L2/L4 |
