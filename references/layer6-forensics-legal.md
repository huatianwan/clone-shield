# L5 · 取证与法律（事后维权，不是当场攻击）

当所有技术层都被突破，还有最后一手：**证明它是抄的**，并有法律抓手。

## 6.1 埋指纹 / 水印 / 蜜标
在自己代码里埋可识别、但不影响功能的标记，被复刻后能举证"这是抄的，不是思路雷同"：
- **代码指纹**：无意义但独特的常量、特定的变量命名序列、刻意的实现怪癖。
- **数据水印**：数据集/配置里埋独特、可追踪的标记项（蜜标，honeytoken）。
- **蜜罐接口**：留一个只有抄你代码才会调用的隐藏接口，对方调了就暴露。
- 记录这些标记的位置和值（保密保存），作为维权证据。

## 6.2 法律抓手
- **用户协议禁止逆向**：写"在适用法律允许的范围内禁止逆向/反编译/复刻"。美国法院执行不统一，但有胜于无。
- **DMCA §1201**：绕过"有效的技术保护措施"本身违法——所以 L1/L3 的技术保护有**法律加成**，这是加固的隐藏价值。
- **商业秘密**：只保护"合法取得后的逆向"之外的窃取；核心逻辑在服务端 = 从没交付 = 更强的商业秘密地位。
- **著作权**：代码受版权保护（但功能不受）。做**软件著作权登记（软著）**，保留开发过程记录（commit 历史、设计文档）作为原创证据。
- **实用专利**：版权只保代码不保功能；能保护"功能构想"的只有专利。核心创新可考虑申请。

## 6.3 发现被复刻后的动作
1. 比对蜜标/指纹，固定证据（公证/时间戳）。
2. 走平台下架（GitHub/App Store DMCA）——注意对"AI 改写版"效果有限。
3. 必要时找律师，用真实证据追责。

## ⚠️ 边界
- 以上是**事后举证**和**合法维权**，不是当场攻击对方、不是伪造指控。
- 蜜罐接口只用于"记录谁调用了它"，不得借此向对方机器投放任何危害性内容。

## 验收
- [ ] 核心代码/数据已埋可举证的指纹/水印（位置已保密记录）
- [ ] 用户协议含禁止逆向条款
- [ ] 已做/已计划软著登记，保留原创证据
